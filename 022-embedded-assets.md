# 022 – Embedding resources: include_str!, include_bytes!, rust-embed; build metadata

## Goal

Ship a CLI as one self-contained file: templates, default configs, images and build metadata
compiled into the binary – nothing to install next to it, nothing to find at runtime.

Example: `examples/022-embedded-assets` – `platctl-new`, a scaffolding tool with embedded templates.

## Key concepts

### Why embed

- one artifact to distribute (`cargo install`, Homebrew, a container `COPY`),
- no runtime lookup (`/usr/share/...`? next to the exe? `$XDG_DATA_DIRS`?) – works from any directory,
- assets always match the binary's version.

Costs: bigger binary, change = rebuild; huge or user-editable assets belong on disk.

### Built-in macros

```rust
const DEFAULT_CONFIG: &str  = include_str!("../assets/default-config.toml");   // UTF-8 text
const LOGO_PNG:       &[u8] = include_bytes!("../assets/logo.png");            // any bytes
include!(concat!(env!("OUT_DIR"), "/generated.rs"));                          // Rust code generated by build.rs
```

- paths are relative to the **source file**, resolved at compile time; a changed file triggers a rebuild,
- the data lives in the read-only data section – no allocation, `'static` lifetime.

### rust-embed – whole directories

```rust
#[derive(RustEmbed)]
#[folder = "templates/"]
struct Templates;

for path in Templates::iter() { ... }                      // Cow<'static, str> paths
let file = Templates::get("service/Cargo.toml.tmpl")?;      // EmbeddedFile { data, metadata }
```

- release builds embed; debug builds read from disk by default (edit templates without recompiling,
  feature `debug-embed` to embed in debug as well),
- features: `compression` (gzip in the binary), `include-exclude` (glob filters), `mime-guess`,
  web framework integrations (axum, actix) for serving embedded frontends.

Alternatives: `include_dir`, `static_files`; for templates combine with an engine (`minijinja`, `tera`).

### build.rs: metadata and generated code

```rust
// build.rs
println!("cargo:rustc-env=GIT_COMMIT={commit}");          // -> env!("GIT_COMMIT")
fs::write(Path::new(&env::var("OUT_DIR")?).join("generated.rs"), code)?;
println!("cargo:rerun-if-changed=templates");             // when to re-run the script
```

```
$ platctl-new --version
platctl-new 0.1.0 (commit 51914b2, built 1790928249)
```

- version info helps bug reports; `vergen`, `built`, `shadow-rs` automate it,
- `SOURCE_DATE_EPOCH` instead of "now" → reproducible builds,
- missing git (crates.io tarball, Docker build without `.git`) must not fail the build – fall back,
- `cargo:rerun-if-changed` – without it the script reruns on every change in the package;
  with it, list everything it reads.

## Example walkthrough

- `assets/default-config.toml`, `assets/logo.png` – `include_str!` / `include_bytes!`.
- `templates/service/**.tmpl` – rust-embed folder, rendered with `{{name}}`/`{{team}}`.
- `build.rs` – git commit, build epoch, generated `TEMPLATE_FILES` constant in `OUT_DIR`.
- `src/main.rs` – `list`, `create` (refuses to overwrite), `default-config`, `logo`, long version;
  tests for embedded data, scaffolding, version.

## Try it

```bash
cargo test -p ex022-embedded-assets
cargo build --release -p ex022-embedded-assets
cd /tmp && /path/to/target/release/platctl-new create demo-svc --team payments   # any directory works
cd demo-svc && cargo run
platctl-new --version; platctl-new list; platctl-new default-config
ls -l target/release/platctl-new        # assets are inside
strings target/release/platctl-new | grep 'Hello from'
```
